## 目标与改动

| 问题 | 根因 | V5.5 本地修复 / 文件 |
| --- | --- | --- |
| 缺少真实 Huashu | 源码包只携带 EDIT-HTML，依赖另一份全局 Skill | `skills/edit-html/vendor/huashu-design/` 内置本机原始快照：173 个文件，保留 MIT 许可证；`src/design-provider.js` 校验逐文件哈希与身份；`scripts/vendor-huashu.mjs` 是显式维护工具，安装器不会重新生成可信清单 |
| 浏览器缺失 / Edge 不可用 | Playwright 被列为开发依赖，启动逻辑分散且没有安装引导 | Playwright 改为运行依赖；`src/browser-runtime.js` 统一 Chromium / Edge / Chrome / 可执行路径；最终预检接入它，`src/design-browser-verification.js` 在锁定验证函数外适配浏览器；`playwright.config.js` 复用选择逻辑 |
| Skill 规范不合法 | 大写 name、顶层 version | 注册目录及名称 `edit-html`，版本移至 `metadata.version: "5.5.0"`；更新 `SKILL.md`、`agents/openai.yaml`、适配文档与相关测试 |
| doctor 误报可用 | 只检查 Node 与 Skill 文件存在 | `src/doctor.js` 分开输出 basicReady / workflowReady；检查 Skill 规范、真实 Huashu、Playwright 及真实浏览器 DOM/JavaScript；CLI 对业务依赖缺失返回非零退出码 |
| 全局命令依赖解压目录 | 直接对源码目录执行 npm global install，生成 junction | `scripts/install-local.ps1` 改用内部临时 npm tarball 安装独立副本；拒绝安装结果仍为链接；旧 Skill 保留在发现目录外，验证失败恢复旧 Skill；`scripts/verify-installation.mjs` 核验安装契约 |

本地曾更新 `README.md`、`README.zh-CN.md` 的安装说明、版本和 Mermaid 流程图；按用户最新要求，这两份 README 的修改不纳入上传和 ZIP，工作目录修改原样保留。更新 Claude Code / Workbuddy 的安装说明，明确 Windows 已验证范围。

设计仍遵循已有自治协议：用户回答内容问题、看到截图后选择 A/B/C；Huashu 主导设计。不恢复位置、配色、版式或 Junior pass 等前置设计确认。内置原始 Huashu 文件未改写，只在 EDIT-HTML 的适配规则中处理冲突与本机路径。

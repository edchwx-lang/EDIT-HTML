# Edit HTML Report：模式与配色重构设计

## 1. 目标

彻底修正当前实现中“报告模式、视觉主题、编辑、发布”互相耦合的问题。

重构后，一份材料只生成一种报告模式的内容结构：

- `data-first`：数据优先，高密度展示 KPI、图表、表格和结构化比较。
- `evidence-first`：证据优先，以文字论证、引文、脚注和原始图表为主。

模式确认并生成报告后，用户在本地编辑器中选择配色。配色只改变颜色，不改变内容、DOM、排版、尺寸、字体、图表类型或信息架构。

## 2. 已确认的产品规则

### 2.1 先模式，后配色

完整流程固定为：

1. 导入并解析材料。
2. Agent 根据材料推荐报告模式。
3. 使用用户的系统语言展示两种模式、推荐项及各自特点。
4. 用户确认唯一模式。
5. 按该模式生成唯一内容结构和 HTML 草稿。
6. 强制打开本地编辑器。
7. 用户编辑内容并在六套配色之间实时切换。
8. 用户保存不可变版本。
9. 用户选择已保存版本和发布渠道后发布。

不得跳过本地编辑器直接把首次生成的草稿当成最终交付物。不得发布未保存草稿。

### 2.2 模式是结构，主题是颜色

模式负责：

- 内容大纲和章节顺序；
- KPI、图表、表格和文字的密度；
- 首屏结构和信息层级；
- 原始图表、引文和脚注的使用方式；
- 页面最大宽度、阅读列宽和网格。

主题负责：

- 页面背景和表面颜色；
- 主文字、次要文字和分隔线颜色；
- 强调色、交互状态色；
- 图表分类色板、连续色板、坐标轴、网格线和提示框颜色。

主题不得包含字体、字号、间距、圆角、阴影、组件尺寸、布局或 DOM 覆盖。切换主题前后的结构散列必须一致。

## 3. 两种模式

### 3.1 数据优先 `data-first`

目标是把材料中的可量化信息转化成可以快速扫描和比较的高密度报告，而不是把文字报告换成深色背景。

设计要求：

- 桌面端使用有左右留白的宽内容容器：`max-width: 1440px`，水平边距使用响应式 gutter。
- 首屏优先放报告结论、可用 KPI 和核心图表，不使用占据大部分视口但信息量很低的装饰性 Hero。
- 图表、表格、流程图必须来自材料事实；不允许为达到数量而编造数据。
- 当材料包含至少 8 个可独立展示的数字事实时，前两个视口至少应出现 4 个 KPI 和 2 个数据可视化模块；整篇优先形成 4 个以上有意义的图表或表格。
- 当源材料不支持上述密度时，明确展示“可量化证据有限”，而不是生成伪图表。
- 所有派生指标都记录公式和来源引用。
- 图表颜色必须实际应用到可见图元，不能只更新元数据或不可见 CSS 变量。

### 3.2 证据优先 `evidence-first`

目标是保留材料原有论证链，以文字说明、原文引用、脚注和原始图表建立可信度。

设计要求：

- 页面使用有左右留白的编辑出版布局；主体容器不铺满屏幕，正文阅读列宽约 `68–78ch`。
- 结论、论据、引文、脚注和来源建立清晰层级。
- 原文中存在图表、示意图或截图时，可直接提取并嵌入，保留标题、说明和来源定位。
- 只有材料中的数据适合结构化表达时才新增图表，不设置强制图表数量。
- 原始图表与 Agent 生成图表在清单中标记不同来源类型。

## 4. 主题系统

### 4.1 独立主题注册表

主题不再写死在 `THEMES_BY_MODE` 或编辑器按钮事件中。运行时从主题注册表发现全部主题。

每个主题使用独立配置文件，建议结构：

```json
{
  "schemaVersion": 1,
  "themeId": "warm-paper-terracotta",
  "labels": {
    "zh-CN": "暖纸赤陶",
    "en": "Warm Paper Terracotta"
  },
  "appearance": "light",
  "tokens": {
    "canvas": "#F5F0E8",
    "surface": "#FFFDFC",
    "surfaceAlt": "#E8DED0",
    "text": "#191919",
    "textMuted": "#6F675F",
    "border": "#D8CEC1",
    "accent": "#CC785C",
    "focus": "#CC785C",
    "positive": "#2F7D63",
    "warning": "#A56A23",
    "negative": "#A63E32"
  },
  "chart": {
    "categorical": ["#CC785C", "#8B6655", "#D9A36F"],
    "grid": "#D8CEC1",
    "axis": "#6F675F",
    "tooltipBackground": "#191919",
    "tooltipText": "#FFFDFC"
  }
}
```

`appearance` 只用于管理界面分组，不参与兼容性判断。所有主题都可以应用于两种模式。

未来新增配色只需：

1. 新增一个通过 schema 校验的主题文件；
2. 补充本地化名称；
3. 生成缩略预览；
4. 通过对比度和图表可辨识度测试。

核心代码、模式模板和编辑器事件逻辑均不需要修改。

### 4.2 首批六套配色

根据 Huashu Design 原风格库筛选并经用户确认，首批保留：

| 编号 | 稳定 themeId | 中文名称 | 外观 | Huashu 来源 |
|---|---|---|---|---|
| L01 | `warm-paper-terracotta` | 暖纸赤陶 | light | Warm Editorial |
| L02 | `research-cobalt` | 研究钴蓝 | light | Dense Research / Utility Docs |
| L06 | `swiss-monochrome` | 瑞士黑白 | light | Swiss Monochrome |
| D01 | `ink-teal` | 墨海荧青 | dark | Dark Editorial |
| D02 | `linear-indigo` | 线性靛蓝 | dark | Linear Look |
| D04 | `signal-orange` | 黑场信号橙 | dark | Black Big-Number Stage |

默认推荐：

- 数据优先：`ink-teal`；
- 证据优先：`warm-paper-terracotta`。

推荐值只是首次选中项，六套配色在编辑器中始终都可选择。

## 5. 生成与编辑架构

### 5.1 模式模板

将模式相关逻辑放入独立 profile：

```text
src/modes/data-first.js
src/modes/evidence-first.js
```

每个 profile 定义报告规划规则、布局约束、内容模块能力和验收指标，不包含具体颜色。

### 5.2 语义颜色契约

生成的 HTML 只引用稳定语义变量，例如：

```css
background: var(--report-canvas);
color: var(--report-text);
border-color: var(--report-border);
```

图表渲染器读取同一份标准化 chart palette。HTML 不直接散落主题十六进制值。

### 5.3 编辑器加载与预览

编辑器启动时读取注册表并展示六张配色缩略图。选择主题后：

1. 将主题 token 注入预览文档；
2. 不重新生成正文或 DOM；
3. 更新项目草稿的 `themeId`；
4. 保持 undo/redo 与内容编辑状态；
5. 用户保存版本时记录选中的 `themeId` 和主题 schema 版本。

不再使用在两个硬编码主题之间循环的 Theme 按钮。

### 5.4 保存与发布

编辑器内明确区分：

- 编辑草稿；
- 保存版本；
- 选择版本；
- 发布。

发布时，从注册表读取已保存版本对应的主题，把选中 token 编译进自包含单 HTML。最终发布文件只固化当前选中的配色，不依赖本地主题目录或远程资源。

## 6. 数据与状态变化

Variant 记录固定模式，Version 记录当时的主题：

```json
{
  "variantId": "...",
  "mode": "data-first"
}
```

```json
{
  "versionId": "...",
  "variantId": "...",
  "themeId": "ink-teal",
  "themeSchemaVersion": 1
}
```

主题切换不创建新的 mode variant。模式需要改变时，必须重新规划并生成新的报告结构，不能通过主题切换伪装成模式变化。

旧项目中的四个历史 themeId 在迁移层映射到最接近的新主题，并在保存新版本时写入稳定 themeId；核心运行时不继续保留旧的硬编码分支。

## 7. 验证标准

### 7.1 单元测试

- 注册表可以发现六套主题并校验 schema。
- 未知 token、缺失 chart palette、重复 themeId 和无效色值会失败。
- 两种模式可以使用任一主题。
- 切换主题不会改变模式、报告计划或内容结构散列。
- 保存版本会固化 themeId；发布只能使用已保存版本。
- 新增第七套测试主题时，不需要修改编辑器或模式代码。

### 7.2 浏览器测试

- 模式确认界面使用用户系统语言，展示两种模式的完整特点和推荐理由。
- 首次生成后自动打开本地编辑器。
- 编辑器展示六张主题缩略图，并能实时切换。
- 两种模式 × 六套主题形成 12 个视觉回归场景。
- 每个场景检查正文、背景、边框及图表图元的 computed color 均非透明且符合主题。
- 图表柱、线、面积和流程节点必须具有可见填充或描边。
- 切换主题前后的 DOM 结构、文本和可编辑节点数量一致。
- 保存后才能发布，发布的是用户选中的不可变版本。

### 7.3 可访问性与离线要求

- 正文与背景、关键 UI 与背景满足 WCAG AA 对比度。
- 图表不能只依赖颜色区分；同时使用标签、形状或直接标注。
- 发布 HTML 断网可完整打开，不请求远程字体、脚本、图片或主题文件。
- 360px、768px、1440px 三档视口无横向溢出。

## 8. 不在本次范围

- 在编辑器中直接把当前报告从数据优先切换为证据优先；
- 允许主题修改字体、间距、卡片形状或布局；
- 自由画布式页面搭建器；
- 为缺少数据的材料编造 KPI 或图表；
- 让最终发布页面依赖在线主题服务。

## 9. 设计依据

- 用户确认：一份材料只生成一个模式，模式决定内容，之后在编辑器中选择配色。
- 用户确认：采用独立主题库、发布时固化所选配色的方案。
- 用户确认：首批保留 L01、L02、L06、D01、D02、D04 六套配色。
- Huashu Design 风格库提供颜色 DNA，但其原风格同时包含字体和布局，不能作为本项目的主题模块直接复用。
- 现有实现把主题写死在模式和编辑器事件中，只替换 `data-theme` 属性，无法支撑未来主题扩展或保证可见渲染。
